# Публикация репозитория — ноль вопросов, один клик

Скрипт публикации **автономный**: не задаёт ни одного вопроса, ничего не ждёт
с клавиатуры. Логин берёт из API, репозиторий создаёт сам, пуш отправляет сам.
Токен при этом не попадает ни в URL, ни в `.git/config`, ни в файлы проекта,
ни в вывод консоли.

> Токен, который уже светился в переписке, — отзови независимо от всего:
> GitHub → Settings → Developer settings → Personal access tokens → Revoke.
> Для пуша выпускай новый (scope `repo` для приватного, для публичного хватит `public_repo`).

## Вариант 0 — Windows, двойной клик (основной)

1. Распакуй архив `universal-agent.zip` в папку.
2. Двойной клик по `PUBLISH.bat`. Всё.

Токен переносить никуда не надо: скрипт **сам** найдёт файл с токеном
(`ghp_...` / `github_pat_...`) в Загрузках, на Рабочем столе, в домашней
папке или рядом с собой (любое имя `.txt`, можно `.gh_token`). Скажет,
в каком файле нашёл. Если репозиторий уже существует — просто допушит.

Найденных токенов может быть сколько угодно (хоть в десяти файлах):
скрипт проверит **каждый** через GitHub API и возьмёт тот, что живой,
а о мёртвых напишет отдельной строкой (файл + отпечаток, сам токен не покажет).
Тег релиза всегда перезаливается (force) на самый свежий коммит — CI на
странице тега будет зелёным, даже если тег публиковался раньше.

## Вариант 0b — Linux / macOS / git-bash

```bash
cd universal-agent
GH_TOKEN=ghp_... bash publish.sh      # или положи токен в любой .txt рядом
# PRIVATE=1 FORCE_PUSH=1 bash publish.sh  — если нужны приватность/перезапись
```

## Что скрипт НЕ делает

- не пишет токен в файлы и не показывает его в консоли (весь вывод проходит
  цензуру `gh*_***[REDACTED]`);
- не задаёт вопросов — при любой ошибке печатает причину и как её чинить;
- не тянет зависимостей: нужны только `git` и `curl` (в Windows 10+ есть из коробки).

## Что уже готово к пушу

- история git: канон-сквош `feat(agent)` с DCO + аннотированный тег `v2.2.0`, ветка `main`;
- `.gitignore` + двойная защита: файлы с токенами выкидываются из индекса
  перед коммитом и из любого вывода при пуше;
- CI `ci.yml`: тесты 3.10–3.12 + check.py-канон + ruff + semantic PR titles;
  зелёная галочка = verify 6/6 и тесты 36/36.

## После пуша

Кинь ссылку на репозиторий в чат. Если он публичный — разберу код, ветки и
open issues прямо по веб-странице (без каких-либо ключей) и подготовлю
следующий PR (этап II: докер-сandbox для `execute_python`).
